## 一、架构总览

### 1.1 模块与分层

按 AGENTS.md 的 Java 项目结构约定：

```
/pom.xml                        聚合根（packaging=pom）
/app/pom.xml                    DDD 聚合（packaging=pom，只声明 modules）
/app/domain                     costlens-domain          领域层，零技术依赖
/app/application                costlens-application     场景编排
/app/infrastructure             costlens-infrastructure  技术实现
/app/adaptor                    costlens-adaptor         入站/出站适配
/common                         costlens-common          通用工具、异常基类、Result
/model                          costlens-model           跨层共享枚举与常量
/client                         costlens-client          对外接口定义与 DTO
/start                          costlens-start           启动模块
```

**依赖方向**（ArchUnit 强制校验）：

```
adaptor → application → domain ← infrastructure
client  → (仅 DTO，不依赖 domain)
common / model  ← 所有层可依赖
```

| 模块 | 允许依赖 | 禁止依赖 |
|---|---|---|
| `domain` | `common`、`model` | 其他一切（Spring、MyBatis、Jackson 均禁止） |
| `application` | `domain`、`common`、`model` | `infrastructure`、`adaptor` |
| `infrastructure` | `domain`、`common`、`model` | `application`、`adaptor` |
| `adaptor` | `application`、`client`、`common`、`model` | `infrastructure`（仓储接口由 domain 暴露） |
| `start` | 全部 | — |

### 2.1 值对象（`com.costlens.domain.{ctx}.model`）

#### Money

```java
public record Money(long minorUnits, Currency currency) implements Comparable<Money> {
    public static Money zero(Currency c);
    public Money plus(Money other);          // 币种不同抛 CurrencyMismatchException
    public Money minus(Money other);
    public Money multiply(Rate rate);        // BigDecimal 中间计算，scale=0 时 HALF_UP
    public Money multiply(long times);
    public Money min(Money other);
    public Money max(Money other);
    public boolean isNegative();
    public int signum();
}
```

**约束**：
- `minorUnits` 是币种最小单位（USD=分，JPY=円，KWD=费尔）
- 构造时校验 `currency == null` 抛异常
- `multiply(Rate)` 实现：

```java
public Money multiply(Rate rate) {
    BigDecimal v = BigDecimal.valueOf(minorUnits)
        .multiply(rate.value())                       // Rate.value() 为 scale=8 的 BigDecimal
        .setScale(0, RoundingMode.HALF_UP);
    return new Money(v.longValueExact(), currency);
}
```

```java
public enum Currency {
    USD(2), JPY(0), EUR(2), GBP(2), MYR(2), THB(2), IDR(0), CNY(2);

}
```

**注意**：`IDR` 最小单位是 1 卢比（无小数），`JPY` 同理。禁止假设所有币种 2 位小数。

### 2.2 聚合根

#### FeeRule（`domain.fee.model`）

**聚合根，写模式**。一条规则身份（`ruleKey`）下挂多个版本，版本只追加不修改。

```java
public class FeeRule {
    private final String ruleKey;
    private final String platform;          // AMAZON_US / AMAZON_JP / SHOPEE_MY / SHOPEE_TH / SHOPEE_ID / TEMU_SEMI
    private final String category;
    private final ChargeType chargeType;    // COMMISSION / PAYMENT / STORAGE / ADVERTISING
    private final List<FeeRuleVersion> versions;

    // 业务时点解析：返回该业务时间生效的版本
    public FeeRuleVersion resolveAt(LocalDateTime bizTime);

    // 认知时点解析（as-of）：返回"截至 knownAt 时，系统认为 bizTime 适用的版本"
    public FeeRuleVersion resolveAsOf(LocalDateTime bizTime, LocalDateTime knownAt);

    // 追加新版本：校验 valid 区间不重叠、recordedAt 晚于已有版本
    public FeeRuleVersion appendVersion(FeeRuleParams params,
                                        LocalDateTime validFrom, LocalDateTime validTo,
                                        LocalDateTime recordedAt);
}
```

**不变量**：
1. 同一 `ruleKey` 下，任意两个版本的 `[validFrom, validTo)` **不得重叠**；
2. 新版本的 `recordedAt` 必须 **严格晚于** 同 `ruleKey` 下所有已有版本的 `recordedAt`；
3. 任何方法都不允许修改已存在的版本（除 `recordedAt` 相同的并发插入由唯一约束拦截）。

## 四、核心算法

### 4.1 运费计费（`domain.freight.service`）

#### 4.1.1 策略选择

```java
public class FreightRatingService {
    private final Map<Market, FreightRateStrategy> strategies;   // US / JP / SEA

    public FreightQuote quote(ShipmentContext ctx, FreightRateSnapshot snap) {
        FreightRateStrategy s = strategies.get(ctx.market());
        if (s == null) throw new UnsupportedMarketException(ctx.market());
        return s.quote(ctx, snap);
    }
}
```

**新增市场** = 实现 `FreightRateStrategy` + 注册到 Map + 建一张费率表，**不改 `FreightRatingService`**。

#### 4.1.2 美国：DimWeightZoneStrategy

```java
public FreightQuote quote(ShipmentContext ctx, FreightRateSnapshot snap) {
    // 1. 体积重（整数运算）
    long divisor = snap.dimDivisor();                       // 5000（cm³/kg）
    long cubicCm = (long) ctx.length().lengthCm()
                 * ctx.length().widthCm()
                 * ctx.length().heightCm();
    long dimGrams = ceilDiv(cubicCm * 1000L, divisor);       // 转克后除，整数运算

    // 2. 计费重 = max(实重, 体积重)，向上进位到 500g 的倍数
    long rawGrams = Math.max(ctx.actualWeight().grams(), dimGrams);
    long billedGrams = ceilDiv(rawGrams, 500L) * 500L;

    // 3. Zone：区间查找
    Zone zone = zoneResolver.resolve(ctx.destZip(), snap.zoneMap());

    // 4. 阶梯单价
    Tier tier = snap.tierOf(billedGrams, zone, ctx.serviceLevel());
    Money base = tier.unitPrice().multiply(billedGrams)     // 单价为"每克"的定点值
                                  .divide(1000L);           // 还原为每公斤

    // 5. 附加费
    Money surcharge = surchargeCalculator.apply(ctx, snap, base);

    return FreightQuote.builder()
        .billedWeight(Weight.ofGrams(billedGrams))
        .dimWeight(Weight.ofGrams(dimGrams))
        .zone(zone)
        .baseFreight(base)
        .surcharge(surcharge)
        .total(base.plus(surcharge))
        .trace(Map.of("divisor", divisor, "rawGrams", rawGrams,
                      "billedGrams", billedGrams, "zone", zone.code()))
        .build();
}

private static long ceilDiv(long a, long b) {
    // 契约：仅接受非负被除数、正除数。Java 整数除法向零截断，负数会让 ceil 语义失效
    if (a < 0 || b <= 0) throw new IllegalArgumentException("ceilDiv requires a>=0, b>0");
    return (a + b - 1) / b;
}
```

```java
public Zone resolve(String zip, ZoneMap map) {
    if (zip == null || zip.length() < 3) throw new InvalidZipException(zip);
    String prefix = zip.substring(0, 5);                     // 保留前导零
    return map.ranges().stream()
        .filter(r -> r.from().compareTo(prefix) <= 0
                  && r.to().compareTo(prefix) >= 0)          // 字符串比较，长度对齐
        .findFirst()
        .map(ZoneRange::zone)
        .orElseThrow(() -> new ZoneUnresolvableException(zip));
}
```

```java
    // 1. 三边和：整数厘米，禁止浮点

    // 5. 附加费（離島 / クール便 / タイムサービス）

    return FreightQuote.builder()
        .girthCm(girth).sizeBand(band)
        .baseFreight(price).surcharge(surcharge)
        .total(price.plus(surcharge))
        .trace(Map.of("girthCm", girth, "band", band.name(),
                      "weightCapGrams", band.weightCapGrams()))
        .build();
}
```

```java
        .continuationUnits(units)

        .total(total)
        .trace(Map.of("excessGrams", excessGrams,
                      "unitGram", rate.continuationUnitGram(), "units", units))
        .build();
}
```

```java
public Money charge(ChargeContext ctx) {
    Money amount = ctx.baseAmount();
    Money sum = Money.zero(amount.currency());
    Money lower = Money.zero(amount.currency());

    for (Tier t : params.tiers()) {                 // 按 lower 升序
        Money upper = t.upper();                    // null 表示无上限
        Money slabTop = (upper == null) ? amount : amount.min(upper);
        Money slab = slabTop.minus(lower);
        if (slab.signum() <= 0) break;

        sum = sum.plus(slab.multiply(t.rate()));
        if (upper == null) break;
        lower = upper;
    }
    return params.cap() == null ? sum : sum.min(params.cap());
}
```

#### 4.2.2 汇总

```java
public FeeChargeResult charge(FeeChargeContext ctx, FeeRuleSnapshot snap) {
    List<FeeRuleVersion> rules = snap.rulesFor(ctx.platform(), ctx.category());

    // 1. 互斥组筛选：同一 mutexGroup 内只保留 priority 最高的一条
    List<FeeRuleVersion> effective = rules.stream()
        .collect(groupingBy(FeeRuleVersion::mutexGroup))
        .values().stream()
        .map(g -> g.stream().max(comparing(FeeRuleVersion::priority)).orElseThrow())
        .toList();

    // 2. 逐项计算后汇总（不做中间合并，保留可解释性）
    List<CostItemDetail> items = effective.stream()
        .map(r -> r.rule().charge(ctx.toChargeContext()))
        .map(money -> toDetail(r, money))
        .toList();

    Money total = items.stream()
        .map(CostItemDetail::computed)
        .reduce(Money.zero(ctx.currency()), Money::plus);

    return new FeeChargeResult(items, total);
}
```

**为什么逐项汇总而不合并**：合并会同时丢失精度与可解释性。用户必须能问"这 30% 是怎么来的"，答案必须能拆成"15% 基础 + 最低收费补足"。

### 4.3 双时态解析（`domain.rule.service`）

#### 4.3.1 解析算法

```java
public class BitTemporalResolver {

    // 业务时点：只看 valid time
    public Optional<RuleVersionRef> atBusinessTime(List<RuleVersionRef> versions,
                                                   LocalDateTime bizTime) {
        return versions.stream()
            .filter(v -> v.validAt(bizTime))
            .max(comparing(RuleVersionRef::versionSeq));
    }

    // 认知时点：valid time + transaction time 双过滤
    public Optional<RuleVersionRef> asOf(List<RuleVersionRef> versions,
                                         LocalDateTime bizTime,
                                         LocalDateTime knownAt) {
        return versions.stream()
            .filter(v -> v.knownAt(knownAt))       // 系统当时已记录
            .filter(v -> v.validAt(bizTime))       // 业务上有效
            .max(comparing(RuleVersionRef::recordedAt));   // 取当时最新的认知
    }
}
```

#### 4.3.2 版本追加（写模式的核心不变量）

```java
public FeeRuleVersion appendVersion(FeeRuleParams params,
                                    LocalDateTime validFrom,
                                    LocalDateTime validTo,
                                    LocalDateTime recordedAt) {
    // 不变量 1：recordedAt 必须严格晚于所有已有版本
    LocalDateTime maxRecorded = versions.stream()
        .map(RuleVersionRef::recordedAt).max(naturalOrder()).orElse(MIN);
    if (!recordedAt.isAfter(maxRecorded)) {
        throw new RuleVersionConflictException(ruleKey, recordedAt, maxRecorded);
    }

    // 不变量 2：valid 区间不得与已有版本重叠
    for (RuleVersionRef v : versions) {
        if (overlaps(validFrom, validTo, v.validFrom(), v.validTo())) {
            throw new RuleVersionConflictException(ruleKey, validFrom, v.validFrom());
        }
    }

    int nextSeq = versions.size() + 1;
    return new FeeRuleVersion(ruleKey, nextSeq, params, validFrom, validTo, recordedAt);
}
```

#### 4.3.3 规则录错了怎么修

**场景**：2023-03-01 录入一条规则，`valid_from = 2023-01-01`，费率误填 5%，实际应为 6%。发现时是 2023-03-10。

**错误做法**：`UPDATE ... SET rate = 6%`。后果——3 月 20 日重算 1 月的账会得到 6%，但 3 月 10 日之前的任何决策都是基于 5% 做的，无法复现。

**正确做法**：

```sql
-- 1. 旧版本收缩 valid_to 到发现日（或干脆不动，见下）
-- 2. 新增一个版本，recorded_at = 2023-03-10，valid_from 覆盖原区间
INSERT INTO fee_rule_version
  (rule_key, version_seq, ..., valid_from, valid_to, recorded_at, remark)
VALUES
  ('AMZ_US_COMMISSION_ELECTRONICS', 2, ..., '2023-01-01', NULL, '2023-03-10 00:00:00', '更正费率 5%→6%');
```

**关键决策**：旧版本是否收缩 `valid_to`？

| 选择 | 后果 |
|---|---|
| 收缩旧版本 `valid_to = 2023-03-10` | 破坏"业务时间"语义：1 月的规则不该在 3 月失效 |
| **不收缩，保留重叠** | 违反不变量 2 |

**本项目采用方案**：**保留重叠，用 `recorded_at` 判优**。即不变量 2 改为"同一 `valid_from` 在**同一 `recorded_at` 视角下**不重叠"。实现上：

```java
// 校验时按 recorded_at 分组，组内不重叠即可
Map<LocalDateTime, List<RuleVersionRef>> byRecorded = versions.stream()
    .collect(groupingBy(RuleVersionRef::recordedAt));
for (var group : byRecorded.values()) {
    assertNoOverlap(group);
}
```

这样：
- `resolveAt(2023-02-15)` → 两条都命中 → 取 `version_seq` 最大（v2，6%）← **日常核算是按最新认知**
- `resolveAsOf(2023-02-15, knownAt=2023-03-05)` → 只有 v1 可见（v2 的 recorded_at 是 3-10）→ 5% ← **复现历史决策**

**这就是双时态的全部价值**：既能让今天的核算用上修正后的规则，又能回答"3 月 5 日那天，系统认为 1 月适用什么费率"。

### 4.4 定价求解（`domain.pricing.service`）

#### 4.4.1 方程形式

设售价为 `x`，固定成本 `F`（采购 + 运费 + 仓储 + 广告），目标毛利额 `P`：

```
x − F − commission(x) − payment(x) = P
⇒ x − commission(x) − payment(x) = P + F =: T   （目标净收入）
```

`commission(x)` 与 `payment(x)` 均为分段函数：

| 规则 | 表达式 | 分段点 |
|---|---|---|
| `PERCENTAGE` | `x · r` | 无 |
| `PERCENTAGE_FLOOR` | `max(x · r, f)` | `x = f / r` |
| `TIERED_BY_AMOUNT` | 分段线性 | 各段 `upper` |
| `PER_UNIT` | 常数（与 x 无关） | 无 |

#### 4.4.2 求解算法

```java
public PricingSolution solve(PricingInput in) {
    // 1. 收集所有分段边界（升序去重）
    List<Money> bounds = new ArrayList<>();
    bounds.add(Money.zero(in.currency()));
    for (FeeRuleVersion r : in.chargeRules()) {
        bounds.addAll(r.rule().breakpoints());        // FLOOR: f/r；TIERED: 各段 upper
    }
    bounds.add(in.priceCap() == null ? Money.of(Long.MAX_VALUE / 2, in.currency())
                                     : in.priceCap().plus(Money.ofMinor(1, in.currency())));
    Collections.sort(bounds);

    // 2. 逐段求解
    for (int i = 0; i < bounds.size() - 1; i++) {
        Money lo = bounds.get(i), hi = bounds.get(i + 1);
        Segment seg = new Segment(lo, hi);            // [lo, hi)

        LinearForm form = linearize(seg, in);         // x − a·x − b = T  ⇒  x = (T + b) / (1 − a)
        if (form.denominator().signum() <= 0) continue;   // 费率 ≥ 100%，该段无解

        Money x = form.solve(in.targetNetRevenue());
        if (seg.contains(x)) {
            return capCheck(x, in);
        }
    }

    // 3. 全段无解
    return PricingSolution.infeasible(in.targetNetRevenue(),
        closestAchievable(in));                       // 返回最接近的可达点，供人工判断
}

private PricingSolution capCheck(Money solved, PricingInput in) {
    if (in.priceCap() == null || solved.lte(in.priceCap())) {
        return PricingSolution.feasible(solved);
    }
    // 核价上限低于所需售价 → 不可行，输出缺口
    return PricingSolution.infeasibleByCap(solved, in.priceCap(),
                                            solved.minus(in.priceCap()));
}
```

#### 4.4.3 `linearize` 的实现要点

在区间 `[lo, hi)` 内，所有 `FLOOR` 与 `TIERED` 规则的分支都已确定，因此：

```java
LinearForm linearize(Segment seg, PricingInput in) {
    Rate a = Rate.zero();                       // x 的系数
    Money b = Money.zero(in.currency());        // 常数项

    for (FeeRuleVersion r : in.chargeRules()) {
        switch (r.ruleType()) {
            case PERCENTAGE -> a = a.plus(r.rate());
            case PERCENTAGE_FLOOR -> {
                // 在 seg 内，x·r 与 floor 的大小关系是确定的
                boolean floorDominates = seg.midpoint().multiply(r.rate())
                                            .compareTo(r.floor()) < 0;
                if (floorDominates) b = b.plus(r.floor());
                else                a = a.plus(r.rate());
            }
            case TIERED_BY_AMOUNT -> {
                // 用 seg.lo 确定命中的子区间，把已走过的段折算成常数
                TierSegResult t = r.rule().tierLinearize(seg.lo());
                a = a.plus(t.marginalRate());
                b = b.plus(t.accumulated());
            }
            case PER_UNIT_BY_MEASURE -> b = b.plus(r.rule().charge(fixedContext(in)));
        }
    }
    return new LinearForm(a, b);
}
```

**关键**：`FLOOR` 的 `floorDominates` 判定必须以区间中点或端点判定并**在解出后回验**，不能只判一次就信。回验失败则继续下一个分段。

#### 4.4.4 输出契约

```java
public record PricingSolution(
    boolean feasible,
    Money solvedPrice,
    Money priceCap,
    Money gap,                 // 不可行时的缺口
    InfeasibleReason reason,   // CAP_EXCEEDED / MARGIN_UNREACHABLE / RATE_TOO_HIGH
    List<SegmentTrace> trace   // 每段的枚举过程，供 UI 展示与调试
) {}
```

**禁止**：不可行时返回一个"接近的"价格而不标记 `feasible = false`。输出"做不到"比输出一个错误的价格有价值。

## 六、状态机与事务边界

### 6.1 成本单状态机

```
DRAFT ──confirm()──► CONFIRMED ──supersede()──► SUPERSEDED
  │                                                ▲
  └──────────────supersede()───────────────────────┘
```

| 迁移 | 触发 | 副作用 |
|---|---|---|
| `DRAFT → CONFIRMED` | 用户确认或自动核算完成 | 锁定明细，不再重算 |
| `* → SUPERSEDED` | 重算产出新单 | 旧单保留，`recalc_batch_id` 关联新单 |

**禁止**：`CONFIRMED → DRAFT`（已确认的单不允许回退，只能被取代）。

### 6.2 重算批次状态机

```
CREATED ──start()──► RUNNING ──allShardsDone()──► FINISHED
                        │
                        ├──首片失败──► FAILED
                        └──部分成功──► PARTIAL
```

### 6.3 事务边界

| 操作 | 事务范围 | 幂等键 |
|---|---|---|
| 生成成本单 | 单库本地事务（成本单 + 明细同库） | `sheet_id` |
| 追加规则版本 | 单库本地事务 | `(rule_key, recorded_at)` |
| 重算批次 | 批次状态 CAS 更新；分片内各自本地事务 | `batch_id` + `shard_id` |
| 账单导入 | 每批 500 行一个事务 | 文件 SHA256 + 行号 |

**跨服务不引入分布式事务**：本系统所有写操作都在单库内，规则快照以只读方式缓存，不存在跨库写。

## 七、失败模式与降级

| 场景 | 检测 | 处理 |
|---|---|---|
| 费率规则缺失 | `resolveAt` 返回 empty | 抛 `RuleNotFoundException`，**不回退默认值**，该单标记 `RULE_MISSING` 不计入毛利 |
| 规则版本区间冲突 | 插入时校验 | 拒绝写入，返回冲突版本号 |
| 同一 `recorded_at` 并发插入 | DB 唯一约束 | 捕获冲突，重试或提示 |
| 邮编非法/无法分区 | 区间查找 empty | 标记待人工，不猜 Zone |
| 三边和超 180cm | `OversizeException` | 拒绝报价，提示走大件渠道 |
| 重量为 0 或缺失 | 前置校验 | 拒绝请求，返回 400 |
| 币种混算 | `Money.plus` 校验 | 抛 `CurrencyMismatchException` |
| 定价无解 | 段枚举完毕无解 | 返回不可行 + 最接近可达点 |
| 核价约束冲突 | `solved > cap` | 返回缺口金额 |
| 重算批次重跑 | `batch_id` 唯一 | 幂等返回已有结果，不重复生成成本单 |
| 分片中途失败 | 批次状态回写 | 置 `PARTIAL`，未完成分片可单独重跑 |
| 规则快照缓存失效 | 缓存 miss | 回源 DB，不回退过期快照 |

**通用原则**：**宁可报错，不可猜测。** 任何"取个默认值让它跑通"的做法，都会在会计链条上放大成错误结论。

```java
@Test
void 多件重量累加不得多算一个续重() {
    // 一个订单两件货：0.2kg + 0.4kg
    Weight total = Weight.ofKilograms("0.2").plus(Weight.ofKilograms("0.4"));

    assertEquals(600, total.grams());          // 整数运算，必须精确

    // 反例：如果实现里用 double 按件累加
    // 0.2 + 0.4            = 0.6000000000000001
    // 减首重 0.5           = 0.10000000000000009
    // ÷ 0.1                = 1.0000000000000009
    // Math.ceil            → 2，多收一个续重

    // 注意：ceilDiv 只对非负数成立，负数场景必须先分支
    long units = total.grams() <= FIRST_WEIGHT_GRAM
        ? 0
        : ceilDiv(total.grams() - FIRST_WEIGHT_GRAM, CONTINUATION_UNIT_GRAM);
    assertEquals(1, units);                     // 600g − 500g = 100g，1 个续重
}

@Test
void ceilDiv_负数场景必须先分支() {
    // Java 整数除法向零截断：(-200 + 99) / 100 = -1，不是 ceil(-2) = -2
    // 所以 ceilDiv 的实现契约限定为非负数输入
    assertThrows(IllegalArgumentException.class, () -> ceilDiv(-200, 100));
}

@Test
void 三边和必须是整数厘米累加() {
    Length3 l = new Length3(26, 27, 27);       // 80cm 恰好落 S80
    assertEquals(80, l.girthCm());
    assertEquals(JpSizeBand.S80, JpSizeBand.ofGirth(l.girthCm()));
}
```
